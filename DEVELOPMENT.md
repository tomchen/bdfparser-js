# Development

Bun 1.4.2 manages dependencies; Node.js (≥ 20; CI uses 20, 22 and 24) runs the
tools.

```sh
bun install --frozen-lockfile
bun run lint        # eslint + prettier --check
bun run typecheck   # tsc --noEmit
bun run test        # vitest
bun run test:cov    # vitest with v8 coverage (text + lcov)
bun run build       # tsup → dist/
```

Commit `bun.lock` when changing dependencies. The library must keep **zero
runtime dependencies** and must not use Node.js APIs (`Buffer`, `fs`, ...)
outside `src/cli.ts`.

## Layout

| path                                         | contents                                                                                     |
| -------------------------------------------- | -------------------------------------------------------------------------------------------- |
| `docs/SPEC-v3.md`                            | specification shared with the Python library (single source of truth)                        |
| `src/Font.ts`                                | `Font`, BDF parser (state machine), editing, `tobdf`, `tosvgfont`, wrappers for PCF / TTF     |
| `src/Glyph.ts`, `src/Bitmap.ts`              | `Glyph` (attached write-back editing) and `Bitmap`                                           |
| `src/encoding.ts`                            | charsets: canonical names (port of the Python `encoding.py`), codecs, GL detection           |
| `src/charsets/`                              | table registry; `table.ts`, `sbcs.ts`, `cjk-data.ts` are GENERATED by `tools/gen_charsets.py` |
| `src/cjk.ts`                                 | sub-module `bdfparser/cjk` (registers the multi-byte tables)                                  |
| `src/pcf.ts`, `src/ttf.ts`, `src/outline.ts` | PCF reader/writer, TrueType reader/writer, bitmap ⇄ outline                                   |
| `src/warn.ts`, `src/errors.ts`               | warning handler, `BDFParseError`                                                             |
| `src/cli.ts`                                 | `bdfparser` command (Node.js only)                                                           |
| `tools/`                                     | `gen_charsets.py`, `check-runtime.mjs`, `check-dts.mjs`, `parity/` (differential harness)     |
| `test/`                                      | vitest suites; `test/fonts/` test fonts; `test/fixtures/golden/` files generated by Python    |
| `examples/`                                  | browser and Node.js examples (no build step)                                                 |

## Builds

`tsup.config.ts` produces `dist/index.js` (ESM), `dist/index.cjs` (CommonJS),
type declarations, `dist/bdfparser.global.js` (minified IIFE exposing the
global `bdfparser`, used by `<script src>` / unpkg / jsDelivr), the
sub-module `dist/cjk.js` / `dist/cjk.cjs` (+ declarations; they import the
core build next to them, `./index.js` / `./index.cjs`, so that the tables
are registered into the core's registry) and `dist/bdfparser-cjk.global.js`
(registers into the global `bdfparser`), and `dist/cli.js` (the `bdfparser`
bin). Only the sub-module and the IIFE scripts have side effects
(`"sideEffects"` in `package.json`).

`node tools/check-dts.mjs` type-checks the published declarations from a
consumer project with `"lib": ["ES2022"]`, `"types": []` and
`skipLibCheck: false` (no DOM, no Node.js types), for `import` and `require`.
`node tools/check-runtime.mjs` (also with `bun` / `deno`) checks the build
against the golden files and the charset fixture.

`test/browser.test.ts` rebuilds the IIFE bundle into a temporary directory and
runs it in a bare `vm` context (no `require`, `process` or `Buffer`) with a
fake canvas and a mocked `fetch`, to make sure the browser build stays free of
Node.js dependencies.

## Parity with the Python library

The Python implementation lives in `../bdfparser`. Behavior differences must
be justified by the spec (language idioms only). Cross-language golden files
in `test/fixtures/golden/` are generated by the Python implementation; JS
tests assert byte equality.

Charsets (SPEC-v3 §11.1): the canonical table and the conversion tables are
generated from the Python library, whose codecs are the reference:

```sh
bun run gen:charsets   # = cd ../bdfparser && uv run python ../bdfparser-js/tools/gen_charsets.py
```

It writes `src/charsets/{table,sbcs,cjk-data}.ts` and
`test/fixtures/charsets.json` (SHA-256 of `cp2char` / `char2cp` over the whole
code space of every charset key, computed by Python; `test/charsets.test.ts`
and `tools/check-runtime.mjs` compare). The canonicalisation functions are
ported by hand from `encoding.py` (checked by the fixture's vectors). Python
versions can differ in their codec tables: regenerate with the Python
version used for the Python library's own release.

`bun run parity` (`python3 tools/parity/run_all.py`, see
`tools/parity/README.md`) runs both libraries on random and corpus cases and
must report 0 NEW divergences.

## Release

1. Update `version` in `package.json`, `VERSION` in `src/constants.ts` and
   `CHANGELOG.md`.
2. Tag `vX.Y.Z` and push the tag: `.github/workflows/publish.yml` tests,
   builds and publishes to npm with provenance (secret `NPM_TOKEN`) and to
   GitHub Packages.
